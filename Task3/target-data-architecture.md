## Детализация по слоям

### 1. Operational Systems

- **FU Core** — мастер по счетам и банковским договорам после cutover.
- **FU Cards** — мастер по картам и карточным транзакциям.
- **FU Loans** — мастер по кредитам и кредитным платежам.
- **FU CRM** — точка консолидации обращений; RB CRM — feeder до cutover.
- **RB Core / RB Cards / RB Loans** — выводятся из эксплуатации по плану Task4.

### 2. Integration Layer

- **ESB** — синхронные запросы (валидация `client_id` в MDM, чтение справочников).
- **Kafka** — асинхронные события: клиентские изменения, транзакции, платежи, обращения.
- **Debezium CDC** — снятие изменений из OLTP-БД без нагрузки на бизнес-логику.
- **API Gateway** — внешние и внутренние API к data products.

### 3. MDM и RDM

- **MDM Customer Hub** хранит golden record клиента и правила матчинга.
- **RDM** хранит продукты, тарифы, отделения, сегменты, коды операций с версиями и владельцами.
- MDM и RDM **не заменяют** операционные системы и не хранят счета/транзакции.

### 4. DWH на PostgreSQL

- Слои: `staging → core (нормализованный) → marts (звезда)`.
- Источник для регламентированной и управленческой отчётности.
- Строится через dbt; оркестрация — Airflow.
- Отделяет OLAP от OLTP; BI не ходит напрямую в Core/Cards/Loans.

### 5. Data Lakehouse (Iceberg + Trino)

- Слои: `bronze (raw) → silver (cleaned/conformed) → gold (curated data products)`.
- Хранит историю транзакций, событий каналов, архивные выгрузки, полуструктурированные данные.
- Используется для ML, антифрода, риск-моделей и глубокой аналитики.
- Trino обеспечивает федеративные запросы между Lakehouse и DWH.

### 6. Object Storage

- Сканы договоров, выписки, архивы выгрузок, документы обращений.
- Версионирование, retention, шифрование, разграничение доступа.

### 7. Graph DB и Search Engine (вспомогательные)

- **Graph DB** — связи клиентов, контрагентов, бенефициаров (AML/антифрод).
- **Search Engine** — поиск по обращениям и клиентским данным контакт-центра.

### 8. BI и регуляторная отчётность

- BI — витрины из DWH и gold-слоя Lakehouse.
- Регуляторная отчётность — из DWH (регламентированные формы), выгрузка по расписанию.

### 9. Управление данными

- **DataHub** — каталог, lineage, владельцы, теги ПДн.
- **Data Quality** — правила в dbt-тестах и Great Expectations, контроль на потоках.
- **IAM / RBAC / ABAC** — доступ к ПДн и финансовым данным.
- **DLP** — маскирование ПДн в обращениях и выгрузках.
- **Audit** — журналирование доступа и изменений.

## Разделение OLTP и OLAP

- Операционные системы — только OLTP.
- Аналитика — DWH и Lakehouse; BI не обращается напрямую к OLTP.
- CDC и Kafka снимают нагрузку с OLTP.
- Trino — федеративные запросы для ad-hoc, без нагрузки на Core.
