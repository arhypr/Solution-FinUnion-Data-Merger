# Стратегия хранения данных

## Принципы

1. Операционные системы FinUnion и RetailBank остаются OLTP-источниками на переходный период.
2. Аналитика не должна создавать нагрузку на OLTP: для отчётности и BI используется DWH, для истории и событий — Data
   Lakehouse.
3. MDM хранит «золотые записи» клиентов и справочников, а не заменяет операционные системы.
4. Документы и выгрузки хранятся в объектном хранилище с версионированием и политикой retention.
5. Поисковый движок используется как вторичный индекс для обращений и поиска по клиентским данным.
6. Графовая БД применяется только там, где связи действительно важны: клиенты, контрагенты, бенефициары, AML/антифрод.

## Распределение по типам хранилищ

| Группа данных                      | Сущности                                   | Тип хранилища                   | Назначение                                                     | Обоснование / ограничения                                                                      |
|------------------------------------|--------------------------------------------|---------------------------------|----------------------------------------------------------------|------------------------------------------------------------------------------------------------|
| Клиентские мастер-данные           | Клиент                                     | MDM                             | Золотая запись клиента, единый party_id, правила сопоставления | Нужен единый профиль; MDM не заменяет CRM, а синхронизирует клиентов                           |
| Справочные данные                  | Справочник, Продукт, Тариф                 | MDM / Reference Data Management | Единые справочники продуктов, тарифов, отделений, сегментов    | Без единых справочников невозможны сопоставление и отчётность                                  |
| Операционные банковские данные     | Счёт, Договор, Карта, Кредит               | OLTP БД                         | Проведение операций, ведение договоров и счетов                | Остаются в Core Banking, карточной и кредитной системах; не используются для тяжёлой аналитики |
| Платёжные и транзакционные данные  | Транзакция, Платёж                         | OLTP БД + event streaming       | Проведение платежей, фиксация операций, антифрод               | OLTP — источник истины; события передаются в Lakehouse для истории и аналитики                 |
| Обращения клиентов                 | Обращение клиента                          | OLTP CRM + поисковый движок     | Ведение обращений и быстрый поиск по текстам                   | Поисковый движок обоснован для контакт-центра и поиска по клиентским данным                    |
| Регламентированная отчётность и BI | Все ключевые сущности                      | DWH                             | Управленческая и регуляторная отчётность, витрины BI           | DWH отделяет OLAP от OLTP и обеспечивает согласованные метрики                                 |
| Исторические и событийные данные   | Транзакция, Платёж, Обращение, события CRM | Data Lakehouse                  | История, raw/silver/gold-слои, event-аналитика, ML             | Позволяет хранить большие объёмы и не нагружать DWH и OLTP                                     |
| Документы и выгрузки               | Договоры, сканы, выписки, архивы           | Объектное хранилище             | Хранение PDF, сканов, выгрузок, архивов                        | Версионирование, retention, шифрование, разграничение доступа                                  |
| Связи клиентов и контрагентов      | Клиент, контрагенты, бенефициары           | Графовая БД                     | AML, антифрод, связанные лица, группы компаний                 | Обосновано только для сценариев связей; не заменяет MDM                                        |
| Поиск по клиентам и обращениям     | Клиент, Обращение                          | Поисковый движок                | Быстрый поиск, полнотекстовый поиск, оперативная поддержка     | Вторичный индекс; источник истины остаётся в OLTP/MDM                                          |

## Целевая логика

- **OLTP**: проведение операций.
- **MDM**: золотые записи клиентов и справочников.
- **DWH**: отчётность и BI.
- **Data Lakehouse**: история, события, неструктурированные данные, ML.
- **Object storage**: документы и архивы.
- **Graph DB**: связи для AML/антифрода.
- **Search engine**: обращения и оперативный поиск.
