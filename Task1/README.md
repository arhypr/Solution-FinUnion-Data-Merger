# Анализ данных, сущностей и хранилищ

## Цель

Проанализировать данные FinUnion и RetailBank, выделить ключевые бизнес-сущности,
описать связи между ними, классифицировать данные по критичности и предложить
типы хранилищ для целевой архитектуры данных.

## Состав решения

- `entities.md` — 11 ключевых сущностей, атрибуты, связи, источники, критерии включения и проблемы качества.
- `logical-data-model.md` — логическая ERD-модель и описание связей.
- `data-classification.md` — классификация данных по категориям, критичности и требованиям ИБ.
- `storage-strategy.md` — распределение данных по типам хранилищ: OLTP, MDM, DWH, Lakehouse, object storage, graph DB,
  search engine.
- `reference-model.md` — маппинг ключевых сущностей на области BIAN.
- `diagrams/erd.puml` — PlantUML-схема логической модели данных (основной источник диаграммы).
- `diagrams/erd.svg` — экспорт диаграммы (опционально, для отображения в GitHub).

## Ключевые архитектурные решения

1. В модель включены 11 сущностей: Клиент, Счёт, Договор, Продукт, Тариф, Карта, Кредит, Транзакция, Платёж, Обращение
   клиента, Справочник.
2. Клиент и справочники — кандидаты на MDM как источники «золотых записей».
3. Операционные системы FinUnion и RetailBank остаются OLTP-источниками на переходный период.
4. DWH используется для регламентированной отчётности и BI, Data Lakehouse — для истории, событий и неструктурированных
   данных.
5. Поисковый движок обоснован для обращений и поиска по клиентским данным контакт-центра.
6. Графовая БД обоснована для связей клиентов, контрагентов и бенефициаров в целях AML/антифрода.
7. BIAN используется как референсная модель для унификации терминологии, границ доменов и будущих data products.

## Допущения

- Детальные модели данных legacy-систем недоступны, поэтому атрибуты описаны на логическом уровне.
- Сотрудники/роли не включены как бизнес-сущность Task1: доступ и права относятся к IAM/RBAC.
- «Тариф» выделен отдельно, так как тарифы карт, кредитов и продуктов различаются и влияют на расчёты и отчётность.
- «Транзакция» и «Платёж» разделены: платёж — инструкция/поручение, транзакция — факт движения средств или операция.
