# Мастер-системы и потоки данных

## Цель

Определить мастер-системы для ключевых сущностей, описать владение данными,
построить DFD для промежуточного состояния (+3 месяца) и описать управление потоками.

## Состав

- `master-systems.md` — роли систем и матрица мастер-систем (As-Is / +3 мес / Target).
- `data-ownership.md` — Data Owner, Data Steward, Producer, Consumer, правила изменения и качества.
- `data-flows.md` — описание основных потоков данных между системами.
- `data-flow-management.md` — таблица управления потоками (SLA, формат, частота, ИБ, мониторинг).
- `data-dependencies.md` — проблемные зависимости и риски на уровне данных.
- `diagrams/dfd-context.puml` — DFD Level 0 (контекстная диаграмма).
- `diagrams/dfd-level1.puml` — DFD Level 1 (детализация промежуточного состояния).

## Ключевые архитектурные решения

1. **MDM Customer Hub** — мастер-система для клиента и точка золотой записи (Party Data Management).
2. **RDM (Reference Data Management)** — мастер для продуктов, тарифов и справочников; не дублирует MDM клиента.
3. **Core Banking, Card Processing и Loan System** остаются мастер-системами для счетов, карт, кредитов, договоров,
   транзакций и платежей. MDM для этих сущностей **не назначается**.
4. **Транзакция и платёж** — события; их мастер — та операционная система, которая провела операцию (Core или Cards).
   Для аналитики они консолидируются в DWH.
5. **DWH** — единая точка регламентированной и управленческой отчётности; отделяет OLAP от OLTP.
6. **Integration Layer (ESB + Kafka + CDC)** — единственная точка маршрутизации потоков; point-to-point интеграции RB
   выводятся из эксплуатации поэтапно.
7. **DataHub / Data Catalog** — метаданные, lineage, владельцы; **не мастер-система**, а инструмент управления.
8. **BIAN** используется для определения границ владения: Party Data Management → MDM; Current Account / Card
   Management / Consumer Loan → операционные системы; Payment Execution / Financial Transaction Capture → Core/Cards;
   Customer Case Management → CRM; Reference Data Management → RDM.

## Допущения

- На старте промежуточного состояния RB Core, RB Cards и RB Loans остаются в работе; их замена — задача Task4 (план
  миграции).
- В переходный период для счетов, договоров, карт, кредитов и транзакций действует «split-master»: FU-системы — мастер
  для FU-клиентов, RB-системы — для RB-клиентов. DWH даёт единое представление.
- Полный cutover на целевую мастер-систему — через 12 месяцев.
- DFD Level 0 показывает внешние сущности, Level 1 — все системы из минимального набора.
