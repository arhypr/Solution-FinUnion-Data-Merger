# Инкрементальный план миграции

## Общая логика

Миграция выполняется волнами. Сначала создаётся фундамент (интеграция, MDM, RDM, DWH), затем переключается клиентский
домен и отчётность, затем консолидируются Cards → Loans → Core, затем выводятся RB legacy.

## План из 8 этапов

| # | Этап                                        | Содержание                                                                                                     | Результат                                         | Exit criteria                                                                    | Длительность        |

| 3 | **Integration foundation**                  | ESB, Kafka, Debezium CDC, API Gateway, Schema Registry, мониторинг                                             | Работающий Integration Layer                      | Пилотный поток CRM → MDM и CDC из Core проходят SLA                              | 6 недель            |

| 6 | **CDC + Lakehouse pilot**                   | Kafka → Spark → Iceberg, bronze/silver/gold, Trino, пилот на карточных событиях                                | Lakehouse pilot                                   | Пилотный поток карточных событий с time travel и lineage                         | 8 недель            |
| 7 | **Consolidation waves**                     | Волна 1: Cards → FU Cards. Волна 2: Loans → FU Loans. Волна 3: Core → FU Core                                  | Консолидированные системы                         | Сверка портфелей, статусов, остатков; cutover-журналы подписаны                  | 15 недель (3 волны) |
| 8 | **Reporting cutover + legacy decommission** | Переключение BI и регуляторики на единый DWH/Lakehouse, остановка RB DWH/BI/Core/Cards/Loans/CRM, закрытие P2P | Целевой ландшафт                                  | RB legacy остановлены; отчётность из единого DWH; DataHub lineage полный         | 5 недель            |

## Детализация волн консолидации

| Волна         | Что переносится                                    | Критичные проверки                                   | Rollback                                                |
|---------------|----------------------------------------------------|------------------------------------------------------|---------------------------------------------------------|
| Wave 1: Cards | Карты, токены, статусы, лимиты, карточные операции | Количество карт, статусы, BIN, сверка операций       | Возврат трафика в RB Cards, остановка записи в FU Cards |
| Wave 2: Loans | Кредиты, графики, остатки, просрочка, скоринг      | Сумма портфеля, остатки, просрочка, графики платежей | Возврат в RB Loans, сверка портфеля                     |
| Wave 3: Core  | Счета, договоры, остатки, платежи, транзакции      | Остатки, обороты, договоры, платежи                  | Возврат в RB Core, сверка остатков                      |

## Зависимости

1. MDM не может быть запущен без Integration foundation.
2. Interim DWH зависит от MDM (`party_id`) и CDC.
3. Lakehouse pilot зависит от Kafka и Schema Registry.
4. Consolidation waves зависят от Interim DWH и сверки.
5. Legacy decommission зависит от успешных волн и подписанной сверки.

## Управление изменениями

- Все изменения целевой модели — через change request и ADR.
- Каждый этап завершается gate review с Data Office, ИБ и бизнес-владельцем.
- Критерии gate: качество данных, сверка, ИБ, производительность, rollback-тест.
