# Технологическая дорожная карта

## Подход

Используется модель зон **Adopt / Trial / Assess / Hold**. Зоны не равны времени: часть Trial переходит в Adopt по мере
готовности, Hold — сознательно не внедряем сейчас.

## Зоны

| Зона       | Технологии и подходы                                                                                                                                                                              | Почему здесь                                                                                                                                                                   |
|------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Adopt**  | MDM Customer Hub, RDM, Kafka, Debezium CDC, ESB, Airflow, dbt, DWH PostgreSQL, BI, DataHub, Object Storage, IAM/RBAC/ABAC, DLP                                                                    | Это фундамент целевой архитектуры. Без них невозможны единый профиль, отчётность, lineage и безопасность. Технологии зрелые, команды имеют компетенции или быстро их получают. |
| **Trial**  | Data Lakehouse: Iceberg + Trino + Spark/Flink; data products с контрактами; Graph DB для AML/антифрод; Search Engine для обращений                                                                | Нужны для целевого состояния, но требуют пилота и подтверждения SLA. Переход в Adopt — после успешного пилота на карточных событиях и сверки с DWH.                            |
| **Assess** | Полный Data Mesh с федеративным governance; Feature Store для ML; real-time ML; SaaS MDM; multi-cloud Lakehouse; streaming-only DWH                                                               | Потенциально полезно, но требует зрелости, бюджета и организационных изменений. Оцениваем после 12 месяцев.                                                                    |
| **Hold**   | Point-to-point интеграции, новые RB Core / RB Cards / RB Loans, локальные справочники продуктов и тарифов, прямые запросы BI к OLTP, ручные сверки в Excel, дублирующие DWH-витрины без владельца | Сознательно не внедряем: противоречит целевой архитектуре, создаёт техдолг и риски.                                                                                            |

## Переходы между зонами

| Технология      | Старт           | Переход                                | Условие                                    |
|-----------------|-----------------|----------------------------------------|--------------------------------------------|
| Iceberg + Trino | Trial в этапе 6 | Adopt к M9–M10                         | Пилот карточных событий, сверка с DWH, SLA |
| Spark/Flink     | Trial           | Adopt к M9                             | Стабильные streaming-пайплайны             |
| Data products   | Trial           | Adopt к M12                            | Контракты, SLA, владельцы, DataHub lineage |
| Graph DB        | Trial           | Assess/Adopt по результатам AML-пилота | Доказанная польза для антифрода            |
| Search Engine   | Trial           | Adopt к M9                             | Поиск по обращениям и клиентским данным    |
| Feature Store   | Assess          | Assess                                 | После запуска Lakehouse и ML-сценариев     |

## Почему не всё сразу Adopt

- Полный Data Mesh и Feature Store требуют зрелых доменных команд и governance.
- Lakehouse — критичен, но сначала пилот, чтобы не сорвать регуляторную отчётность.
- Graph DB и Search Engine — вспомогательные; их ценность нужно доказать, а не внедрять «на всякий случай».
- Hold защищает от возврата к P2P и локальным справочникам.

## Связь с этапами миграции

- Этапы 1–3: Adopt — ESB, Kafka, Debezium, Airflow, Schema Registry.
- Этапы 4–5: Adopt — MDM, RDM, DWH PostgreSQL, dbt, DataHub.
- Этап 6: Trial → Adopt — Iceberg, Trino, Spark/Flink.
- Этапы 7–8: Adopt — data products, BI на едином DWH/Lakehouse, decommission RB legacy.
